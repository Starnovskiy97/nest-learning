# План изучения бэкенда и NestJS

## Цель

Разобраться в архитектуре NestJS: назначении модулей, контроллеров и сервисов,
внедрении зависимостей, взаимодействии модулей и обработке HTTP-запросов.

Учебный проект — менеджер задач, который постепенно обрастает возможностями.
Начинаем с минимального приложения, без базы данных, авторизации и Docker.
Менеджер пакетов — pnpm.

## Формат обучения

Каждый шаг: короткое объяснение → небольшое изменение → запрос к серверу →
разбор результата. Тесты добавляем по ходу работы.

Не добавляем архитектурные слои и механизмы только ради их наличия:
для каждого должна появиться понятная задача.

## 1. Основы и первый модуль: задачи

- Разобрать существующие `AppModule`, `AppController` и `AppService`.
- Создать `TasksModule`, `TasksController` и `TasksService`.
- Добавить создание задачи и получение списка задач.
- Хранить данные в памяти, без базы данных.

Структура:

```text
src/tasks/
├── tasks.module.ts
├── tasks.controller.ts
└── tasks.service.ts
```

Что изучаем:

- Controller принимает HTTP-запрос и возвращает ответ.
- Service выполняет логику приложения.
- Module объединяет компоненты и описывает их зависимости.
- Dependency Injection: как Nest создаёт сервис и передаёт его контроллеру.

Путь запроса:

```text
HTTP-запрос → Controller → Service → результат → HTTP-ответ
```

## 2. Полноценный HTTP API

- Добавить получение одной задачи, изменение и удаление.
- Разобрать HTTP-методы, параметры URL и тело запроса.
- Выбирать подходящие HTTP-коды ответа.
- Обработать случай «задача не найдена».

## 3. DTO и проверка входных данных

- Добавить DTO и валидацию: нельзя создать задачу без названия.
- Разобрать отличие DTO от модели данных.
- Изучить pipes на примере проверки и преобразования входных данных.
- Понять, почему TypeScript сам по себе не проверяет данные HTTP-запроса.

## 4. Второй модуль: пользователи

- Добавить `UsersModule`.
- Реализовать назначение задачи пользователю.
- Организовать взаимодействие `TasksModule` и `UsersModule`.

Что изучаем:

- `imports`, `providers` и `exports`.
- Область доступности сервисов между модулями.
- Границы ответственности модулей.
- Причины циклических зависимостей и способы их избежать.

## 5. Постоянное хранение данных

- Заменить массив в памяти на базу данных.
- Выбрать базу данных и ORM на этом этапе, а не заранее.
- Разделить хранение данных и бизнес-логику.
- Разобрать схему данных, миграции и связь между пользователем и задачей.

## 6. Доступ и жизненный цикл запроса

- Добавить авторизацию и ограничения доступа к задачам.
- Проследить путь запроса через механизмы NestJS.
- Подбирать механизм под конкретную задачу, а не добавлять всё сразу.

Механизмы:

- Middleware — предварительная обработка, например логирование.
- Guard — проверка, можно ли выполнять запрос.
- Pipe — проверка и преобразование входных данных.
- Interceptor — действия вокруг обработчика.
- Exception Filter — обработка исключений.

## Ближайший шаг

Разобрать существующие `AppModule`, `AppController` и `AppService`,
затем собрать аналогичный `TasksModule` с созданием задачи и получением списка.
